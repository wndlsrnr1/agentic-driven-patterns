# Server Config Docs Readability Template (Strict)

## 공통 원칙
- 목표: "빠르게 읽히되, 사실 누락 0".
- 전략: `30초 요약 카드 + 상세 근거` 2단 구조.
- 금지: 의미 삭제, 근거 없는 일반화, 표 전체 제거, 파일 경로 변경.

## 패밀리 A (개별 9문서)

### 헤더
```md
# <doc-title>

> [!NOTE] 30초 요약
> - 이 파일이 담당하는 결정 1줄
> - 누가 읽고 언제 적용되는지 1줄
> - 바꾸면 깨지는 핵심 1줄
```

### 섹션 구조 (고정)
1. `## 0. 독자와 목표`
2. `## 1. 한눈에 보는 오버뷰`
3. `## 2. 파일 문법 설명`
4. `## 3. 프레임워크-모듈-라이브러리 연결`
5. `## 4. 키별 시니어 해설`
6. `## 5. 라이프사이클 타임라인`
7. `## 6. 패러다임 및 아키텍처 관점`
8. `## 7. 초보자가 헷갈리는 포인트`
9. `## 8. 변경 전 체크리스트`
10. `## 9. 3줄 요약`

### 섹션별 필수 요소
- `0`: 대상 독자, 목표, 대상 파일, 관련 근거 파일, 용어 브릿지
- `1`: 존재 이유/시스템 위치/소비 주체/영향 범위
- `2`: 문법/파서 규칙/오해 포인트
- `3`: 소비 주체 연결표
- `4`: 요약 표 + 상세 설명 블록
- `5`: build/start/request/ops 타임라인
- `6`: 계층/DI/DDD/운영 안정성 관점
- `7`: 오해 2개 이상
- `8`: 실행 가능한 체크리스트(명령 포함)
- `9`: 핵심 3문장

### 표 사용 규칙
- 요약 표: 유지 (`키`, `현재값`, `어디서 읽는가`, `변경 영향` 최소 포함)
- 상세 설명 블록: 표 아래에 키별 설명 추가
- 초대형 10열 표는 허용하되, 앞에 `요약 표`를 먼저 둔다

## 패밀리 B (인덱스 1문서)

### 필수 구조
1. 문서 목적
2. 9개 심화 문서 링크
3. 핵심 상호작용 그래프
4. 라이프사이클 타임라인
5. 권장 읽기 순서
6. 공통 체크리스트
7. 인덱스 운영 원칙

### 필수 문자열
- `ADP_BUILD_MODE -> package.json -> tsconfig.build*.json -> Dockerfile`
- `jest.config.ts <-> tsconfig.json(NodeNext/ESM)`

## 작성 규칙 (엄격)
- 한 문장 한 주장.
- 핵심 주장에는 소비 주체/라이프사이클 근거를 붙인다.
- `왜 중요한지`를 메커니즘으로 설명한다.
- 전문용어 첫 등장에 1줄 용어 브릿지 제공.

## 금지 패턴
- 과도한 폭 표만 있고 요약이 없는 구조
- 동일 내용 반복(표와 본문 중복 복붙)
- 콜아웃 남용(`[!NOTE]`, `[!TIP]` 다중 중첩)
- 언어 혼입/오탈자/어색한 번역어
- 체크리스트에서 실행 불가능한 모호 표현

## 검증 체크리스트
- [ ] 10개 문서 모두 템플릿 패턴 준수
- [ ] 각 문서 상단에 `30초 요약` 카드 존재
- [ ] FACT-ID 기반 핵심 사실 누락 없음
- [ ] 인덱스 필수 문자열 2개 유지
- [ ] `요약 표 + 상세 설명 블록` 적용
