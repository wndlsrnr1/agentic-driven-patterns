# Korean Docstring With Project Context (TypeScript)

## 목적

프로젝트 전체와 하위 디렉토리에서 TypeScript/React JSDoc을 작성할 때, Google 스타일과 Effective Java 원칙을 결합해 한국어로 작성한다. 처음 보는 사람이 호출 흐름, 사용 위치, 변수/클래스/함수 역할까지 이해할 수 있도록 맥락 정보를 반드시 포함한다.

## 적용 범위

- TypeScript/React: JSDoc 스타일 주석

## 핵심 원칙 (Google + Effective Java)

- API 계약을 문서화한다: 전제조건, 후속조건, 부작용, 예외 조건, 스레드 안전성.
- 요약은 한 줄, 명확한 동작/역할을 표현한다.
- 타입 시그니처에 이미 있는 정보는 반복하지 말고, 의도/규칙/범위/단위/기본값을 기록한다.
- 문서가 코드보다 오래 남는다는 전제로 유지보수 가능성을 최우선으로 한다.
- 프로젝트 맥락을 반드시 포함한다: 호출 위치, 사용 목적, 관련 클래스/모듈, 데이터 흐름.

## 필수 맥락 정보 (누락 금지)

모든 public/protected 대상과 핵심 로직에는 아래 정보를 포함한다.

- 호출자/사용자: 어떤 클래스/레이어가 호출하는지
- 사용 시점/목적: 언제, 왜 사용되는지
- 역할/범위: 변수/클래스/함수가 시스템에서 맡는 책임
- 데이터 흐름: 입력이 어디서 오고 결과가 어디로 가는지
- 부작용: 네트워크 호출, 상태 변경, 캐시 갱신, 이벤트 발행
- 예외/오류: 어떤 조건에서 발생하는지

## 작성 절차

1. 대상 식별: 컴포넌트/훅/함수/유틸 중 문서화 대상 선택.
2. 호출 흐름 파악: 참조/호출 위치를 검색한다 (LSP references, Grep).
3. 맥락 메모 작성: 호출자, 관련 모듈, 데이터 흐름, 부작용을 정리.
4. 요약 작성: 한 줄 요약 + 빈 줄.
5. 상세 작성: 맥락, 규칙, 예외, 스레드 안전성 순으로 기록.
6. 예시 추가: 필요 시 UI/데이터 흐름 예시.

## TypeScript/React JSDoc

### 규칙

- 요약 한 줄 + 맥락/규칙/부작용 순으로 정리.
- `@param`, `@returns`, `@throws` 사용.

### 템플릿

```ts
/**
 * [한 줄 요약]
 *
 * Context:
 * - 호출자: [컴포넌트/훅/서비스]
 * - 사용 목적: [UI/데이터 흐름]
 * - 데이터 흐름: [입력 -> 처리 -> 출력]
 *
 * Side effects:
 * - [네트워크/상태 변경]
 *
 * @param param [의도/제약]
 * @returns [반환 의미]
 */
```

## 금지 사항

- 호출 위치/사용 맥락을 생략하지 않는다.
- 타입 시그니처에 있는 정보만 반복하지 않는다.
- 구현 상세(조건문/루프 구조 등)만 설명하지 않는다.
- 근거 없는 추측을 쓰지 않는다. 호출자/흐름은 반드시 확인 후 기록한다.

## 빠른 체크리스트

- 요약 한 줄이 명확한가
- 호출자/사용 목적/데이터 흐름이 포함됐는가
- 전제조건/후속조건/부작용/예외가 포함됐는가
- 한국어로 작성했는가
- 문서가 처음 보는 사람의 이해를 돕는가
